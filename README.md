# ses-worklog

**ローカルLLM を組み込んだ Web アプリケーションを実装することを目的とした個人開発プロジェクト。**

題材として、SES 技術者が客先常駐先での業務内容を手元に蓄積し、
自社への報告や職務経歴の整理に使える形へ変換する仕組みを扱う。

扱うデータの性質上、外部の生成 AI サービスへは送れない。
そのため推論をすべてローカルで完結させる構成とし、
「LLM に任せる処理」と「決定論的に処理すべきもの」の切り分けを設計の中心に据えている。

## できること

### 1. 日次メモの秘匿化と蓄積

自由記述の走り書きから固有名詞を除去し、報告に使える抽象度へ変換して蓄積する。

```
入力（走り書き）
  ↓ ① 辞書による決定論的マスキング   … LLM 非依存
  ↓ ② ローカルLLM による文脈的抽象化 … LLM 未接続時は自動で縮退
  ↓ ③ 出力側での再マスキング         … 最終ゲート
  ↓ ④ 残存検査
蓄積（生ログは AES-256-GCM で暗号化して保存）
```

### 2. 作業記録の構造化

繰り返し発生する定型作業は、文章ではなくマスタからの選択で記録する。

```
定型作業（案件・作業種別を選択。種別は複数選択可）
  ↓ LLM 不使用
  ├→ 日別の作業内容テキスト
  └→ 週次の件数集計（構造化データを数えるだけなので誤りが入らない）
```

### 3. 週報の下書き生成

```
非定型メモ（日次メモの自由記述）
  ↓ LLM
  └→ 週次報告の 2 文目（その週固有の貢献）
```

生成物は下書きであり、外部システムへの書き込みは行わない。

## セットアップ

### 前提

- **Java 17 以上**（必須）
- **Ollama**（任意。無くても辞書マスキングのみで動作する）

Maven は同梱の Wrapper が自動取得するため、事前インストールは不要。

### 手順 1: 暗号鍵を用意する

生ログは客先の機密を含みうるため暗号化して保存する。
**鍵が無いとアプリは起動しない**（平文保存を防ぐための意図的な設計）。

鍵を生成する（PowerShell）:

```powershell
$b = New-Object byte[] 32
[Security.Cryptography.RandomNumberGenerator]::Create().GetBytes($b)
[Convert]::ToBase64String($b)
```

出力された値を `src/main/resources/application-local.yml` に記述する。
このファイルは Git 管理外。

```yaml
worklog:
  crypto:
    key: <上で生成した Base64 文字列>
```

> **鍵を失うと保存済みの生ログは復号できなくなる。**
> マスキング済みの列は平文で保持しているため、週報生成に必要なデータ自体は失われない。

### 手順 2: 起動する

Windows:

```
mvnw.cmd spring-boot:run
```

macOS / Linux:

```
./mvnw spring-boot:run
```

`http://localhost:8080` を開く。初回起動時に動作確認用のマスタが自動投入される。

### 手順 3: ローカルLLM を有効にする（任意）

未接続でも動作するが、文脈的な抽象化は行われない。

```
ollama pull qwen3.5:9b
```

`application.yml` の `worklog.llm.model` を `ollama list` に表示される実際のタグへ合わせる。
Ollama 以外を使う場合は `base-url` の差し替えだけで動く。

画面右上に接続状態が表示される。

| 表示 | 意味 | 対処 |
|---|---|---|
| LLM 接続中 | 設定モデルが取得済みで利用可能 | — |
| LLM 未設定（モデル未取得） | サーバは動作しているが設定モデルが無い | `ollama pull` するか設定を修正 |
| LLM 未接続（辞書マスキングのみ） | サーバに到達できない | Ollama を起動する |
| LLM 無効（辞書マスキングのみ） | 設定で無効化されている | `worklog.llm.enabled=true` |

#### reasoning_effort は必ず設定すること

思考型モデルは既定で思考モードが有効になっており、この状態では
**思考だけで文脈上限に達し、本文が生成されない**。

実測値:

| 設定 | 所要時間 | 結果 |
|---|---|---|
| 未指定 | 90 秒 | 思考に 3839 トークンを消費し `finish_reason=length`、本文は空 |
| `reasoning-effort: none` | 1 秒 | 正常に本文を返す |

思考内容は `<think>` タグではなく **`reasoning` という別フィールド**で返るため、
タグの除去では防げない。設定で抑制するしかない。
対応しないサーバでは `reasoning-effort` を空文字にすればフィールドごと送信しない。

## 使い方

| 画面 | パス | 用途 |
|---|---|---|
| 作業記録 | `/work` | 定型作業をマスタから選択して記録する |
| 日次メモ | `/` | 非定型の気づき・改善を自由記述で残す |
| 週報 | `/weekly` | 週単位で集計し、下書きを生成する |
| 禁止用語辞書 | `/terms` | 伏せる固有名詞を登録・管理する |

### 作業記録と日次メモの使い分け

判断基準は「**その作業を来月もやるか**」。

| | 作業記録 | 日次メモ |
|---|---|---|
| 対象 | 繰り返す定型作業 | 一度きりの変化・改善・気づき |
| 入力方法 | マスタから選択 | 自由記述 |
| LLM | 使わない | 使う |
| マスキング | かけない | かける |
| 記入頻度 | 毎日 | 該当する日だけ（週 1〜2 回で十分） |

日次メモはマスキングを通るため、**固有名詞を気にせず走り書きしてよい**。
一方、作業記録はマスキングを通らないため、そのまま報告に載せられる内容だけを記録する。

### 典型的な運用

1. **毎日** — `/work` で案件・作業種別を選び、対象を入力する
2. **変化があった日** — `/` に走り書きを残す
3. **週末** — `/weekly` を開き、集計と下書きを確認してコピーする

## パッケージ構成

```
com.example.worklog
├── config       初期データ投入・スキーマ移行
├── crypto       生ログの保存時暗号化
├── domain       エンティティとリポジトリ
├── masking      禁止用語辞書と決定論的マスキング
├── abstraction  ローカルLLM クライアント
├── pipeline     秘匿化パイプライン
├── weekly       週報の集計と生成
└── web          コントローラ
```

| パッケージ | 責務 | 主なクラス |
|---|---|---|
| `config` | 起動時のマスタ投入と、`ddl-auto` では行われないスキーマ移行 | `MasterDataSeeder`, `WorkEntryTaskTypeMigration` |
| `crypto` | 生ログ列の AES-256-GCM 暗号化。JPA の `AttributeConverter` で透過的に処理する | `EncryptedStringConverter`, `CryptoKeyHolder` |
| `domain` | エンティティと Spring Data リポジトリ | `DailyLog`, `WorkEntry`, `ForbiddenTerm`, `Project`, `TaskType` |
| `masking` | 辞書による決定論的な置換。宛先別の強度切替と、辞書未登録の固有名詞候補の検出 | `MaskingService`, `TermDictionary`, `MaskingProfile`, `RiskScanner` |
| `abstraction` | OpenAI 互換エンドポイントへの補完リクエスト、疎通確認、思考モード抑制 | `LlmClient`, `LlmStatus`, `LlmProperties` |
| `pipeline` | マスキングと抽象化を組み合わせた秘匿化の一連の流れ | `SanitizePipeline`, `DailyLogService` |
| `weekly` | 週境界の算出、作業内容テキストの組み立て、件数集計、報告文の生成 | `ReportWeek`, `WorkContentFormatter`, `WeeklyReportService`, `PerformanceGenerator` |
| `web` | 画面のコントローラとフォーム | `WorkEntryController`, `WeeklyReportController`, `HomeController` |

依存の向きは `web → pipeline / weekly → masking / abstraction → domain`。
`masking` は LLM に依存せず、`abstraction` が停止しても単独で機能する。

## 処理の流れ

秘匿化パイプライン（`SanitizePipeline`）:

```
生入力
  ↓ ① 辞書による決定論的マスキング   必須・LLM 非依存
  ↓ ② ローカルLLM による文脈的抽象化 任意・失敗しても縮退
  ↓ ③ 出力側での再マスキング         最終ゲート
  ↓ ④ 残存検査（アサーション）
最終出力
```

③ を置いているのは、LLM が ② の入力（マスク済み）しか見ていない以上
原理的には禁止用語を出力できないが、辞書更新との競合などで再出現しうるため。
③ は決定論的処理なので、通過後の出力に辞書用語が残らないことを保証できる。

## 設計上の重要な決定

### 1. 秘匿化の一次防衛線に LLM を使わない

LLM に「固有名詞を隠して」と依頼する方式は取りこぼしが原理的に避けられない。
禁止用語辞書による決定論的な置換を必須の一次処理とし、
LLM は「文脈的な言い換え」だけを担当する。

結果として、**LLM が停止しても秘匿化の安全性は下がらない**（品質だけが下がる）。
この縮退設計により、ローカルLLM という可用性の読みにくい依存を安全に組み込める。

### 2. 日本語のマッチングに正規表現の単語境界を使わない

日本語には語境界が存在しないため `\b` が使えない。
辞書マッチングは Aho-Corasick で行い、最長一致を優先することで
「株式会社ABC」と「ABC」の競合時に壊れた出力にならないようにしている。

補助的な `RiskScanner` では正規表現を使うが、Java の `\b` は
`Character.isLetterOrDigit` で境界を判定するため漢字も単語構成文字とみなされる。
「伝票番号20260827001」のように日本語と数字が直結すると境界が成立せず検出漏れになるため、
単語境界ではなく前後の文字種を否定先読み／後読みで直接指定している。

### 3. 決定論的にできることは LLM に任せない

件数の集計、テキストの組み立て、定型文の選択はいずれも構造化データからの
機械的な処理として実装している。生成に置き換えれば実装は短くなるが、
**誤りが混入する余地を作ることになる**。

集計値が構造化データを数えた結果であることは、報告内容の裏付けとしても意味を持つ。

### 4. マスキング強度は宛先ごとに変える

| プロファイル | 案件名・システム名 | 人名・その他 |
|---|---|---|
| `INTERNAL`（社内報告） | 残す | マスク |
| `EXTERNAL`（職務経歴・社外） | マスク | マスク |

社内向けの報告では案件名が残っていないと内容が伝わらない一方、
社外に出る職務経歴では伏せる必要がある。既定は `EXTERNAL` とし、安全側に倒している。

### 5. 仕様は推測せず実データで検証する

週単位の集計に使う「年月週」は、ISO 週番号とも「月内の第 n 月曜」とも異なる独自規則だった。
月曜起点だが週が月をまたがず、第 1 週は月初日から、最終週は月末日で切り詰められる。
月末が週明けに落ちる月は第 6 週まで存在する。

推測で実装せず、過去 219 週分の実データと突き合わせて全件一致を確認したうえで実装し、
`ReportWeekTest` で境界条件を固定している。ここがずれると集計も生成もすべて狂う。

### 6. 生成物に「書くことが無い」を許容する

報告文の生成では、該当する内容が入力に無ければ**何も生成しない**。
埋めようとした瞬間に、入力に存在しない事実の生成が始まるため。

### 7. 生ログは暗号化して保持する

破棄せず持つのは、辞書を改善したあとに過去ログを再処理できるようにするため。
DB 上が暗号文であることは `DailyLogPersistenceTest` で検証している。

## テスト

```
mvnw.cmd test
```

秘匿化とテキスト生成の中核は決定論的処理として実装しているため、
**LLM 無し・インメモリ DB で全件検証できる**。

| テスト | 検証内容 |

| `ModelMatchingTest` | モデルタグの照合 |

## セキュリティ上の注意

- **サーバは既定で `127.0.0.1` にのみバインドしている。**
  外部から接続できるようにする場合は認証の追加が前提（現時点では未実装）。
- **暗号鍵（`application-local.yml`）は Git 管理外。** 共有する場合も鍵は含めない。
- **業務内容を報告に書ける範囲は、個別契約と NDA によって決まる。**
  本アプリは「書ける範囲の中で表現を整える」ためのものであり、
  書けないものを書けるようにするものではない。

## 既知の制約

- 認証機構なし。単一利用者のローカル実行のみを想定。
- `spring.jpa.hibernate.ddl-auto=update` を使用。列の削除やデータ移行は行われないため、
  スキーマ変更時は `WorkEntryTaskTypeMigration` のような移行処理を個別に書いている。
  Flyway を導入した時点で移行スクリプトへ置き換える。
- マスタ（禁止用語・案件・作業種別・定型文）の編集は削除や無効化で代替する。更新機能は未実装。
- 外部システムへの書き込みは行わない。生成物はコピーして貼り付ける運用とする。
- `spring-boot:run` は JVM をフォークするため、Maven を停止してもアプリが残る場合がある。
  H2 のファイルロックが解放されず再起動に失敗したら、残存 java プロセスを終了させること。
